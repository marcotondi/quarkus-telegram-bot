= Quarkus Telegram Bot

include::./includes/attributes.adoc[]

A Quarkus extension for Telegram bots: CDI annotations, Mutiny, and generated Bot API 8.x models. The transport (webhook or long polling) is picked automatically.

== Features

* Handlers declared with `@TelegramCommand`, `@OnMessage`, `@OnCallbackQuery`, `@OnInlineQuery`, `@OnChosenInlineResult`, `@OnState`, `@OnStateMismatch`, `@OnError`. Details in xref:handlers.adoc[Handlers & Routing].
* Multi-step conversations with `ConversationContext`, stored in memory or Redis. Details in xref:conversations.adoc[Conversations & FSM].
* Per-handler restrictions through `@SecuredBot`, `@BotAdmin` and `@ChatType`. Details in xref:security.adoc[Security & Authorization].
* 230+ Java 21 records and sealed interfaces covering the Bot API, plus `InlineKeyboard` builders.
* Uploads of photos, documents, audio and media groups through `InputFile.BinaryPath` and `InputFile.BinaryBytes`.
* WireMock-backed `ConversationSimulator` for testing bot flows. Details in xref:testing.adoc[Testing Bots].

== Requirements

* Java 21
* Quarkus 3.40.x

== Installation

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>io.quarkiverse.telegram</groupId>
    <artifactId>quarkus-telegram-bot</artifactId>
    <version>{project-version}</version>
</dependency>
----

== Configuration

Minimal `application.properties`:

[source,properties]
----
quarkus.telegram.token=123456789:ABCdefGhIJklmNoPQRsTUVwxyZ
quarkus.telegram.mode=AUTO
----

`AUTO` polls Telegram in dev and test mode, and uses the webhook in production. Every key with its default is in xref:config-reference.adoc[Configuration Reference]; transport behavior is described in xref:transports.adoc[Transports & Configuration].

== First handler

[source,java]
----
package com.example;

import jakarta.enterprise.context.ApplicationScoped;

import io.quarkiverse.telegram.bot.runtime.api.TelegramCommand;
import io.quarkiverse.telegram.bot.runtime.model.Chat;
import io.quarkiverse.telegram.bot.runtime.model.SendMessage;
import io.quarkiverse.telegram.bot.runtime.model.User;

@ApplicationScoped
public class GreetingBot {

    @TelegramCommand(value = "/start", description = "Avvia il bot")
    public SendMessage start(User user, Chat chat) {
        return SendMessage.builder()
                .chatId(chat.id())
                .text("Benvenuto, " + user.firstName() + "!")
                .build();
    }
}
----

Returning a `String` sends a plain text reply to the current chat and needs no `chatId`:

[source,java]
----
@TelegramCommand("/ping")
public String ping() {
    return "pong";
}
----

== Run

[source,bash]
----
mvn quarkus:dev
----

Command descriptions declared on `@TelegramCommand` are registered with Telegram through `setMyCommands` at startup.
